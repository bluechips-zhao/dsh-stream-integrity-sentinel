# 项目章程

## 1. 项目名称

`dsh-stream-integrity-sentinel`

## 2. 问题陈述

DSH 的适配器把供应商流翻译成 `StreamChunk`，Agent Loop 随后累积、展示、持久化并执行其中的工具调用。宽容汇编器可提高兼容性，但空或变化的 call ID、重复 ID、块类型冲突、结束后继续输出、无效 JSON 参数等异常，可能在更晚阶段表现为未知工具、错误工具关联、界面失败、不可回放会话或错误执行。

现有相邻工具多聚焦单一故障并尝试修复或中和。该项目要提供一个统一、可审计、拒绝猜测的执行前验证边界。

## 3. 产品目标

- **G-001**：任何未通过 v1 流规则的工具调用不得到达 Agent Loop 的工具执行路径。
- **G-002**：健康流按字节等价的 chunk 值和原始顺序放行。
- **G-003**：默认失败关闭，且不自动构造模型没有明确给出的身份、名称或参数。
- **G-004**：资源消耗有硬上限，取消与 iterator cleanup 可证明。
- **G-005**：诊断足够定位规则，但不记录工具参数或会话正文。
- **G-006**：使用官方公共扩展面，以独立 bundle 安装，不修改 DSH 源码。

## 4. 非目标

- **NG-001**：不验证供应商原始 HTTP/SSE 字节。
- **NG-002**：不证明适配器语义翻译忠实；如果适配器输出已经错误但内部自洽，插件可能无法识别。
- **NG-003**：不自动修复、重编号、补名、截断参数或猜测合法 JSON。
- **NG-004**：不修复已经持久化的历史会话。
- **NG-005**：不替代工具 schema 验证、权限、审批、沙箱或 OS 隔离。
- **NG-006**：不保证覆盖绕过 `ctx.llm.stream()` 的自定义调用链。

## 5. 目标用户

- 使用多个 OpenAI-compatible 网关或第三方适配器的 DSH 用户；
- 需要工具调用审计和稳定会话记录的开发团队；
- 编写/验证 DSH 适配器的维护者；
- 在 CI 中对合成流做兼容性回归的插件作者。

## 6. v1 范围

### 6.1 受保护调用

默认条件：`GenerateOptions.tools` 存在且长度大于 0。可按 provider/model include/exclude，但配置不能扩大插件能观察的技术边界。

### 6.2 受保护不变量

- chunk 运行时形状合法；
- index 是非负安全整数；
- 同一 index 的 block 类型不冲突；
- tool-call 身份非空、稳定且在一次响应内唯一；
- tool 名称最终非空，非空值不得变化；
- tool arguments 累积后为合法 JSON；
- `block-end` 与累积值一致；
- 块不会重复关闭，关闭后无迟到 delta；
- usage 在 finish 前；
- 恰好一个 terminal finish，之后无 chunk；
- 隔离缓冲、块数和 chunk 数不超过配置上限。

### 6.3 操作模式

- `enforce`：默认。违规时丢弃隔离流尾，输出一个 `STREAM_INTEGRITY_VIOLATION` 错误 finish，不放行工具调用。
- `observe`：完整原样放行，只输出脱敏诊断；明确不提供保护，仅用于兼容性评估。

v1 不提供 repair 模式。

## 7. 成功指标

- 合成违规语料库中，所有预期违规均被确定性识别；
- 健康语料库和真实官方适配器流零变更放行；
- 违规测试中 `executeToolCalls` 调用次数为 0；
- 健康流输出 chunk 深度相等且顺序相同；
- 超限、取消、清理测试无未决 iterator、无无界内存增长；
- 新 profile 安装、Web/headless 启动、卸载恢复全部通过。

## 9. 已知产品风险

- 同类/相邻工具已经存在，创新性是组合和可证明边界，不是绝对首创。
- 严格规则可能拒绝非标准但可被 DSH 容忍的供应商流。
- 流尾隔离会增加第一次工具片段之后的显示延迟和内存开销。
- `always` 重试策略可能对 sentinel 错误重复请求，必须在验收中验证并给出配置警告。
- 上游 API 尚在预发布阶段，兼容性需要按 commit 声明。
