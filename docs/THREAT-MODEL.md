# 威胁模型

## 1. 保护资产

- Agent Loop 不执行身份或参数不完整的工具调用；
- 会话的 assistant/tool 关联不被明显异常流污染；
- 下游 UI、重放和严格供应商不接收可预见的非法工具块；
- 用户内容、推理、工具参数和凭据不因诊断泄露；
- 宿主资源不因恶意或失控流无界增长。

## 2. 对手与故障来源

- 不完全兼容 OpenAI/DeepSeek 协议的网关；
- 有缺陷的官方或第三方适配器；
- 生成矛盾 tool call 的模型；
- 改写 `llm/stream` 的其他插件；
- 恶意适配器主动构造资源耗尽或状态混淆流；
- 操作人员使用错误 profile、错误插件顺序或不兼容 DSH 版本。

## 3. 信任假设

- sentinel 的 listener 确实位于所有待防护输出的最终外层；
- Agent Loop 只消费该 listener yield 的 chunk；
- error finish 不触发工具执行；
- Node/Cordis/DSH 宿主本身未被同进程恶意代码完全控制。

同进程插件拥有主机级能力。恶意插件可以卸载 sentinel、注册更外层 listener、直接执行工具/文件操作或篡改运行时，因此本项目不是对抗恶意宿主插件的隔离边界。

## 4. 威胁与缓解

| ID | 威胁 | 影响 | 缓解 | 剩余风险 |
| --- | --- | --- | --- | --- |
| T-001 | 后续空 ID 覆盖先前 ID | 错误关联、会话污染 | 每个 delta ID 非空且同 index 稳定 | 适配器若已隐藏原始变化则不可见 |
| T-002 | 不同 index 复用 call ID | UI/结果关联冲突 | 响应内唯一性检查 | 跨 turn 复用不在 v1 范围 |
| T-003 | index 复用合并两个调用 | 参数/名称混合，可能执行错误工具 | 类型、ID、name 稳定性 | 适配器预先合并成自洽流时漏报 |
| T-004 | 无效 JSON 参数 | 工具失败、严格回放 400 | 完成时 JSON.parse，违规不放行 | 语义错误仍由 tool schema 处理 |
| T-005 | block-end 与 delta 不同 | 权威块覆盖正确累积值 | 三字段严格比较 | 非工具扩展块只做不透明验证 |
| T-006 | finish 后继续输出/重复 finish | 汇编结果不确定 | 读至 iterator done 后再放行尾部 | 恶意 iterator 永不结束受取消/上限约束 |
| T-007 | 大量/巨大 chunk | 内存或 CPU 耗尽 | 四类硬上限、失败关闭 | 到达上限前仍有受限成本 |
| T-008 | 诊断泄露参数/提示词 | 隐私泄露 | 诊断 API 不接收正文，测试日志 sink | 宿主其他日志仍可能记录流 |
| T-009 | 更外层插件事后改写 | 绕过 sentinel | profile 顺序探针与停止条件 | 同进程恶意插件无法彻底防御 |
| T-010 | `always` retry | 重复请求、成本失控 | 稳定非默认重试码、启动警告 | 用户主动配置 always 仍会重试 |
| T-011 | 取消与 flush 竞态 | 用户取消后仍执行工具 | abort 优先、取消时不 flush、竞态测试 | 宿主信号实现漂移 |
| T-012 | sentinel 自身异常 | fail-open 或会话中断 | 自身错误合成失败 finish | 极端运行时错误可能阻止生成器继续 |
| T-013 | 错误版本/接口漂移 | 失效或启动崩溃 | commit 预检、兼容矩阵、fresh profile | 预发布上游变化频繁 |
| T-014 | observe 被误当 enforce | 用户误信保护 | 明确模式标识与启动告警 | 运维忽略告警 |

## 5. 绕过路径

以下路径不受保护：

- 适配器在产生 `StreamChunk` 前已经把原始事件错误合并，且产出仍满足全部不变量；
- 自定义代码绕过 `ctx.llm.stream()` 直接调用供应商或工具；
- 其他插件在 sentinel 之后修改流；
- 直接写会话存储、修改历史或伪造 tool result；
- shell、MCP、IDE 或其他非 Agent Loop 路径发起的操作；
- 恶意同进程插件修改 sentinel 配置或实现。

## 6. 误报模型

- 第三方适配器依赖 DSH 宽容行为，例如重复 block-start、缺失 finish、空 continuation ID；
- 合法但非规范的 tool arguments 不是 JSON；
- 扩展 chunk type 未被 sentinel 版本识别；
- 超大但合法工具参数超过本地限额。

缓解方式是先使用 observe 建立兼容语料、调整有界上限或为明确的上游契约增加版本化规则；不得通过自动修复把歧义流变成可执行流。

## 7. 漏报模型

- 供应商原始流的语义冲突被适配器完全吞掉；
- 两个错误调用被翻译成一个格式自洽但语义错误的调用；
- 合法 JSON 包含业务上危险或错误的值；
- call ID 在不同 turn/session 被重用并触发下游历史问题；
- 工具本身或批准策略存在缺陷。

## 8. 安全声明模板

允许的声明：

> 在已验证的 DSH 版本和 profile 顺序下，sentinel 阻止违反已列规范化 `StreamChunk` 规则的工具调用进入 Agent Loop 执行路径。

禁止的声明：

> sentinel 能保证模型原始意图不被篡改、拦截所有恶意工具调用、保护所有 DSH 文件/工具操作，或提供进程隔离。
